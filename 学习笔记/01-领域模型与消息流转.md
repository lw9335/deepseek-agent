## 一句话理解

整个系统就是一个**工单系统**：有人在飞书 / GitHub 上提了件事 → 系统判断要不要接 → 接了就开工单 → 派一个 AI worker 去做 → 做完回到原处回复。

## 术语对照（用一个例子串起来）

例子：小王在飞书"前端群"的一个话题里发："@agent 帮我修一下登录页点提交就白屏的问题"

| 名词 | 中文 | 在例子里是什么 | 一句话理解 |
| --- | --- | --- | --- |
| Source | 来源 | 飞书 | 消息从哪个平台来（另一个是 GitHub） |
| Trigger | 触发 | 小王发的这一条消息 | 一条消息 = 一个 Trigger，发出后不可变 |
| Thread | 话题串 | "登录页报错"这个话题 | 一个帖子 + 下面所有回复。**不是编程里的"线程"，也不是整个群** |
| Eval | 评估 | 判断小王有没有权限、是不是新请求 | 前台。两层：准入 gate（查名单）+ 研判 assessment（模型判断） |
| Mandate | 授权 | "小王明确请求修登录页，依据第 3 版规则批准" | 批准时开的授权书，写明能做什么、依据什么 |
| Ticket | 工单 | "修复登录页白屏" | 一件批准了的活，只有 Eval 能开 |
| Assignment | 派工 | 派给 `worker-123` | 工单和干活的人之间的绑定（一张工单可先后换几个 worker） |
| Executor | 执行器 | `worker-123` 这个 Session + 工作目录 | 真正动手的 AI |
| Channel | 渠道 | 回到原话题里回复 | 结果写回到哪里 |
| Subscription | 订阅 | 工单订阅"登录页报错"这个话题 | 话题里以后的新消息自动转给工单 |
| Fan-out | 扇出 | 新消息被抄送给订阅它的工单 | 订阅的具体动作 |

### 容易混的几对

- **Trigger vs Thread**：一条消息 vs 这条消息所在的那串对话。
- **Ticket vs Executor**：这件活 vs 干活的人。分开是因为干活的人可以换，工单要一直在。
- **Thread vs Session**：
  - Thread 是**人**在飞书 / GitHub 上的聊天串；
  - Session 是 **AI** 自己的工作对话（思考、工具调用、命令输出）。
  - 人在 Thread 里说话 → 消息送进 worker 的 Session → worker 再把回复发回 Thread。

## Thread 在代码里怎么定义（飞书）

[feishu-trigger.ts:16](../dsh-superagent-prototype/src/sources/feishu-trigger.ts)：

```ts
export const feishuThreadId = (chatId, rootId, messageId) => `${chatId}:${rootId ?? messageId}`
```

**Thread 编号 = 群编号 : 这串回复最开头那条消息的编号**

```
小王：@agent 登录页白屏         messageId=om_1  不是回复 → Thread = oc_前端群:om_1
  └ 小李（回复）：只在 Safari     rootId=om_1    → Thread = oc_前端群:om_1  ✅ 同一串
小张：今天谁值班？               messageId=om_9  不是回复 → Thread = oc_前端群:om_9  ❌ 另一串
```

所以订阅的是"帖子"不是"整个群"，worker 不会被群里闲聊打扰。GitHub 那边一个 Issue / PR 就是一个 Thread。

## 一条消息进来后的两条路

```
新消息进来
   │
   ├─ 所在 Thread 被工单订阅了？──是──▶ 直接送给 worker（代码判断，不用模型）
   │
   └─ 否 ──▶ Eval（主 Session 用模型判断）
               ├─ accept  → 开新工单（带 Mandate）
               ├─ attach  → 挂到已有工单（必须"明确指向"它）
               ├─ stop    → 叫停某张工单
               └─ ignore / unavailable → 不处理，记录下来
```

对应图里：`T → K`（Subscription fan-out，快路） 和 `T → E`（Eval）。

### 判断"是不是同一件事"分三层

1. **Source 贴话题标签**（不用模型）：平台本身告诉你消息属于哪个话题 / Issue。
2. **Intake 查订阅**（不用模型）：话题被订阅就送给工单，否则进 Eval。
3. **worker 在自己 Session 里理解内容**（用模型）：不相关就 `orchestrator_trigger_handback` 退回，退回的消息再走 Eval。

主 Session 不参与第 3 层，消息也不进主 Session 的上下文。

## 核心代码：[intake.ts](../dsh-superagent-prototype/src/core/intake.ts) `receive()`

```ts
for (const ref of trigger.threads) {             // 消息属于的每个话题
  const thread = this.thread(ref)
  for (const ticketId of thread.subscriptions) { // 订阅了这个话题的每张工单
    const followed = !!thread.context?.includes(ticketId)
    const resumes = trigger.human && ticket?.ended?.by !== 'human' && !followed
    if (!ticket || (!liveTicket(ticket) && !resumes)) continue
    reached.set(ticketId, ...)                   // 记下"要送给这张工单"
  }
}
for (...) this.tickets.addInput(ticket, ...)     // 放进工单的 Input
if (!this.owners(trigger).length) this.queueForEval(trigger)  // 没有工单负责 → 去 Eval
for (const ticketId of fanout) this.tickets.wake(ticketId)    // 唤醒 worker
```

**已结束的工单要被恢复，三个条件必须同时满足：**

1. `trigger.human`：发消息的是人，不是机器人 / CI
2. `ended.by !== 'human'`：工单不是被人叫停的
3. `!followed`：是工单自己的话题，不是 worker "顺便跟着看"的话题

## 关键规则（附文档出处）

- **订阅过来的人的消息不经过 Eval**（第 7 行）。被否决的设计："追加到 Ticket"这种 Decision —— 追加就是订阅扇出，不需要 Eval（第 53 行）。
- **转过去的只是上下文，不带权限**。范围变大要开新工单（第 34 行："更大的范围意味着新的 Ticket"）。
- **主 Session 只有在消息明确指向某个已有工单时才 attach**（第 37 行），不能猜着挂。
- **叫停只能由 Eval 决定**，worker 不能自己宣布"有人让我停"（第 57 行）。
- Eval 的准入还会查发消息的人**有没有权限**（允许名单在 Policy 里）。

### 正常做完 vs 被人叫停

核心差别：**这件事的授权（Mandate）还在不在。**

| 工单怎么结束的 | 授权 | 话题里有人再说话 |
| --- | --- | --- |
| worker 正常做完 | **还在**（做完不代表收回） | 直接恢复旧工单，沿用原 Mandate，**不走 Eval** |
| 被人叫停（stop） | **被收回** | 旧工单不再接收，消息**走 Eval**，判断后可能开新工单 |

文档原话（第 34 行）："Ticket 结束不会让它结束：只有人的停止会收回它"。

## 练习题回顾

| 问题 | 答案 |
| --- | --- |
| 小李在**同一话题**里补一句"只在 Safari 出现"，要再过 Eval 吗？ | 不用，订阅扇出直接送给 worker |
| 工单正常结束后，小王在原话题说"又白屏了"？ | 直接恢复旧工单，不走 Eval |
| 小李**另起一条消息**（不是回复）说"登录页那个只在 Safari 出现"？ | 新 Thread（`oc_前端群:om_10`），没被订阅 → 进 Eval → 主 Session 可以 attach 到已有工单 |
| 小李另起一条说"登录页别修了"？ | 进 Eval → stop |
| 被叫停的工单，小王又在原话题回复"又白屏了"？ | `ended.by === 'human'` → 不恢复 → 走 Eval，可能开新工单 |
