第 6 章　提示词逐个精读：给团队一份能执行的工作手册

这一章按真实文件逐个拆开读。先看“这段交代谁做什么”，再看“哪句在防哪种错误”，最后辨认程序到底强制了多少。全章的例子沿用同一请求：有人请 agent 改 README 的错别字；我们希望它改对、验证、发出可审查的 PR，并把结果送回原评论。

💡 打个比方

餐厅有全员手册、前台岗位卡、后厨岗位卡，还有“怎么处理外卖平台订单”的小册子。手册告诉人应该怎么做；门禁与收银机决定实际能做什么。提示词和工具权限也有这样的区别。

📌 精确地说

Prompt（提示词）是每次模型请求收到的指令文本；system prompt 是宿主以系统指令方式提供的部分。Skill 是按需加载的操作知识，像平台办事指南。配置里的规则、来源消息和工具返回的数据都有不同身份，不能只因排在上下文后面就自动获得更高授权。

6.3　强弱顺序：门禁硬约束排在员工手册前面

文档给出的顺序是：工具和宿主强制的事实 → 内置及生成段（含团队 override 后的文本）→ 主动 Ticket 命中规则中的流程与沟通 → 团队段与团队 skills → 外部文本。这是系统希望模型遵守的关系；只有代码检查的部分才是硬边界，不能把整套文字顺序说成模型必然服从的安全证明。 dsh-superagent-prototype/docs/004-prompts.md:65

⚠️ 注意
