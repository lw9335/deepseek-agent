# 000 理念

dsh-superagent 是一个框架，也是一种与 agent 协作的方式。它的核心原则是：

**尽可能少地占用人的注意力，尽可能多地提供价值。**

项目的每个部分都按它消耗的注意力来评判。一条消息、一个通知、一个问题、一项设置、一个面板元素、一段文档，都会消耗某个人的注意力，每一样都必须提供多于这份消耗的价值，否则就删掉。

## 对 agent 意味着什么

- **只在被要求、或有成文规则允许时才行动。** 只有直接对 agent 说话、并且来自团队允许的人（在允许名单上的人，或在团队开放请求的对话里的任何人）的请求才算数。没人要求的工作需要一条团队写下的规则，并且从一个只记录 agent 本会做什么的模式开始。
- **只在有人必须行动或能用上结果时才说话。** 它对一个请求确认一次，并说明要做什么。工作时保持安静。当结果就绪、需要决定、或无法完成时，它才再次发言。消息简短，并发到提出请求的那个对话里。
- **一次只问一个具体问题，** 而且用结构化的形式，让问题真正送到人那里，而不是埋在一份长报告里。
- **按影响而不是按工作量来决定何时停下。** 局部改动一直做到可评审的结果。需要设计决策的改动，以一个清晰的问题停下。
- **如实报告。** 草稿标为未完成，失败报告为失败，绝不为了避免提问而绕过限制。

## 对设计意味着什么

- **概念少。** 设计中只有它的领域概念（例如 Source）及其具体实现（例如 GitHub 和飞书）。一个业务需求会变成其中某个概念的属性，或 agent 遵循的一段提示词。设计不会为它新增一个概念。
- **设置少。** 当某个取值几乎适合所有团队时，就用默认值代替设置。团队用文字描述的行为是提示词文本，不是设置。
- **面板只显示需要人处理的东西。** 它首先列出等待人处理的事项。健康的状态不占空间。
- **文档按顺序阅读。** 每篇编号文档只建立在之前的文档之上，所以读者永远不会遇到一个还没被介绍的概念。

## 责任

agent 会用你的团队每天都能看到的账号去评论、开 pull request、给人发消息。它发出的每条消息都会消耗你同事的注意力，而你要为此负责。agent 能做的越多，它的操作者就越应对团队用心：

- **从窄处开始。** 先用一个短的允许名单，主动工作只做记录。等 agent 本会做的事看起来是对的，再把两者放宽。
- **为减少噪音而调整。** 当 agent 太吵时，把它的提示词改得更短、更严格，或者暂停它。不要添加更多消息去解释这些噪音。
- **不要用它来制造数量。** 大量的 pull request、群发消息和凑数的工作，给团队带来的成本大于价值。
- **为它说的话负责。** 阅读 agent 以你的名义发布的内容，它错了就在提示词里纠正。

目标是在正确的时间给出正确的帮助，其他时间什么都不做。
