## 一、模型架构层：把记忆做进模型

| 工作 | 核心思路 | 认可度 / 备注 | 本地 |
|---|---|---|---|
| **Titans**（Google，2025，arXiv 2501.00663） | 神经记忆模块在推理时把"意外"信息写进参数，配合注意力处理超长上下文 | 引用很多，后续工作的基础 | 📄 `2501.00663v1.pdf` |
| **ATLAS**（同团队，arXiv 2505.23735） | 改进 Titans 的记忆更新规则，提升记忆容量 | 中等 | 📄 `2505.23735v1.pdf` |
| **Nested Learning / HOPE**（NeurIPS 2025） | 把模型看成多层、不同更新频率的嵌套优化；记忆分多个时间尺度（Continuum Memory System），目标是持续学习不遗忘 | 讨论度高；效果为作者自报，未见独立复现 | 📄 `2512.24695v1.pdf` |
| **DeepSeek Engram**（2026-01） | MoE 之外的新稀疏维度：O(1) N-gram 查表式"条件记忆"；计算与查表之间的参数分配呈 U 形 scaling 规律；100B 参数表放主机内存开销 <3% | 与 deepseek 研究直接相关，建议精读。"会用于 V4"的说法属媒体猜测 | 📄 `2601.07372v1.pdf` |

链接：
- Nested Learning：https://arxiv.org/abs/2512.24695 ／ Google 博客：https://research.google/blog/introducing-nested-learning-a-new-ml-paradigm-for-continual-learning/

## 二、后训练层：用 RL 让模型学会管理记忆

2025 下半年到 2026 增长最快的方向。共同做法：把"写什么 / 删什么 / 取什么"当成模型的动作，用最终任务的结果当奖励。

| 工作 | 要点 | 本地 |
|---|---|---|
| **MemAgent**（arXiv 2507.02259） | 分段读超长文本，边读边用 RL 训练覆写一块定长记忆；读得再长显存也不涨，外推到超长上下文掉点很少 | 📄 `2507.02259v2.pdf` |
| **MEM1**（MIT，arXiv 2506.15841） | 每步把记忆和推理合并成一个持续更新的内部状态，长任务中上下文大小恒定 | 📄 `2506.15841v2.pdf` |
| **Memory-R1**（arXiv 2508.19828） | 两个 agent：Memory Manager 做增删改，Answer Agent 筛选记忆并作答；PPO/GRPO 训练。很省数据，约 152 条 QA 即超过基线 | 📄 `2508.19828v5.pdf` |
| **Mem-α**（arXiv 2509.25911） | 用 RL 学构建分层记忆（核心 / 情景 / 语义） | 📄 `2509.25911v1.pdf` |
| **Memex(RL)**（arXiv 2603.04257） | 带索引的经验记忆，用于长周期 agent | 📄 `2603.04257v1.pdf` |
| **CompactionRL**（arXiv 2607.05378） | 把上下文压缩纳入 RL 训练，模型自己学会总结和续接；后训练与 harness 的交汇点 | 📄 `2607.05378v2.pdf` |

## 三、Agent Harness / Loop 脚手架层

工业界共识：长记忆主要靠 harness 解决，不靠更长的上下文窗口。

### 3.1 上下文工程与压缩（compaction）
- 常见组合：按 token 阈值触发总结，超大工具输出落盘、只留引用，子 agent 隔离上下文，工具 schema 按需加载。Anthropic、OpenAI、微软框架都已内置服务端 compaction。
- 相关论文：
  - Code as Agent Harness：https://arxiv.org/abs/2605.18747 📄 `2605.18747v1.pdf`
  - Less Context, Better Agents：https://arxiv.org/abs/2606.10209
  - CliffCompaction（长周期编码 agent 的低成本压缩）：https://arxiv.org/abs/2609.26779
  - TokenPilot（压缩与 prompt cache 命中率的权衡）：https://arxiv.org/abs/2606.17016
  - When History Is Multimodal（多模态历史的上下文管理）：https://arxiv.org/abs/2608.29897

### 3.2 跨会话的长时运行 loop
- **Anthropic《Effective harnesses for long-running agents》**（2025-11）
  https://anthropic.com/engineering/effective-harnesses-for-long-running-agents
  - initializer agent 只跑一次：生成 `feature_list.json`、`claude-progress.txt`、`init.sh`、首个 git commit。
  - 之后每个会话的 coding agent：先读进度文件和 git log → 一次只做一个功能 → 提交并更新进度。
  - 记忆就是文件系统加 git，不需要额外的记忆库。
- **Ralph loop**（Geoffrey Huntley，据我所知）：最简单的 `while true` 循环，每轮给干净的上下文，重复喂同一份 prompt 和规格，状态全放在仓库文件里。思路与上面一致，只是更简陋。

### 3.3 自我进化的经验记忆（不改权重，只改 context）
- **ACE / Agentic Context Engineering**（ICLR 2026，arXiv 2510.04618）📄 `2510.04618v3.pdf`
  https://arxiv.org/abs/2510.04618 ／ 代码：https://ace-agent.github.io/
  - Generator、Reflector、Curator 三个角色维护条目化 playbook。
  - 只做增量更新、不整体重写，因为整体重写会导致记忆坍缩（论文里有一例从约 1.8 万 token 缩到 122，掉到无记忆基线以下）。
  - 每条记录有 ID 和"有用 / 有害"计数器。
- **ReasoningBank**（Google，2025，据我所知）、**Dynamic Cheatsheet**、**Agent Workflow Memory**：从成功和失败的轨迹里提炼可复用的策略或工作流。
- **Skills / SKILL.md**：把经验固化成按需加载的技能文件，可以看作 Voyager 技能库的工程化版本。

### 3.4 记忆系统产品
- Letta（MemGPT 后继；提出 **sleep-time compute**：空闲时异步整理记忆）
- Mem0、Zep / Graphiti（时序知识图谱）、MemOS

### 3.5 Harness 资料汇总
- awesome-agent-harness（RUCAIBox）：https://github.com/RUCAIBox/awesome-agent-harness
- awesome-harness-engineering：https://github.com/ai-boost/awesome-harness-engineering
- Modern Agent Harness Blueprint 2026（社区整理，非官方）：https://gist.github.com/amazingvince/52158d00fb8b3ba1b8476bc62bb562e3

## 四、记忆的组织与分类

核心问题：记忆存成什么形态、按什么维度分类、怎么随时间整合、更新和遗忘。

### 4.1 分类框架（先建立术语）

| 工作 | 分类维度 |
|---|---|
| **Rethinking Memory in LLM based Agents**（arXiv 2505.00675） 📄 `2505.00675v3.pdf` | 按**表示**分：参数化 / 上下文结构化 / 上下文非结构化；按**操作**分：整合、索引、更新、遗忘、检索、压缩。适合作为全文的术语底座 |
| **Anatomy of Agentic Memory**（arXiv 2602.19320） 📄 `2602.19320v2.pdf` | 给出 agent 记忆的分类体系，并实证分析现有评测和系统的局限 |
| **MIRIX**（arXiv 2507.07957） 📄 `2507.07957v1.pdf` | 按**认知类型**分六类：Core / Episodic / Semantic / Procedural / Resource / Knowledge Vault，每类由一个专门的 manager agent 负责，上面有 meta manager 统一路由 |
| **Is Agent Memory a Database?**（arXiv 2605.26252） 📄 `2605.26252v1.pdf` | 从数据库视角重新审视记忆的数据基础：数据模型、一致性、事务、索引 |

常见的认知科学式划分是：工作记忆（上下文窗口）、情景记忆（发生过什么）、语义记忆（事实与知识）、程序性记忆（技能与流程，对应 skills / playbook）。

### 4.2 组织结构：四种主流形态

**① 分层 / 操作系统式**（按冷热和访问频率分层）
- **MemGPT**（arXiv 2310.08560） 📄 `2310.08560v2.pdf`：开山之作。上下文窗口相当于内存，外部存储相当于磁盘，由模型通过函数调用自己换页。Letta 是它的工程化后继。
- **MemOS**（arXiv 2507.03724） 📄 `2507.03724v4.pdf`：把记忆当系统资源统一调度，覆盖记忆单元的创建、调度和演化全生命周期；区分参数记忆、激活记忆（KV cache）和明文记忆。
- **MemoryOS**（arXiv 2506.06326） 📄 `2506.06326v1.pdf`：短期、中期、长期三级，记忆按热度在层间晋升（据我所知）。

**② 按类型路由**
- **MIRIX**：写入时先判断属于哪类记忆，再交给对应 manager。

**③ 图 / 笔记网络**（强调关联和时间）
- **A-MEM**（arXiv 2502.12110） 📄 `2502.12110v11.pdf`：Zettelkasten 卡片盒式。每条交互生成原子笔记，带关键词、标签和上下文描述，自动和旧笔记建立链接，新笔记还会反过来更新旧笔记（memory evolution）。缺点是构建很慢，有综述测出约 15 小时。
- **Zep / Graphiti**（arXiv 2501.13956） 📄 `2501.13956v1.pdf`：时序知识图谱，事实带有效时间区间，能表达"以前是 A、现在是 B"。
- **HippoRAG**（arXiv 2405.14831） 📄 `2405.14831v3.pdf`/ **HippoRAG 2**（arXiv 2502.14802） 📄 `2502.14802v2.pdf`：模仿海马体索引，用知识图谱加 Personalized PageRank 做多跳联想检索。HippoRAG 2 把它定位为"非参数化持续学习"。
- **GAM**（arXiv 2604.12285） 📄 `2604.12285v1.pdf`：分层图记忆，把**编码**和**整合**分开，只在语义边界处更新全局图，避免每轮都重构。
- **MRAgent / Memory is Reconstructed, Not Retrieved**（arXiv 2606.06036） 📄 `2606.06036v1.pdf`：Cue–Tag–Content 三层图，查询时由 LLM 决定怎么遍历，把记忆当成"重建"而不是"取出"。作者承认这张图是静态的，没有持续更新和遗忘。

**④ 自适应选结构**
- **Choosing How to Remember**（arXiv 2602.14038） 📄 `2602.14038v1.pdf`：不同任务适合不同的记忆结构（列表、树、图等），让 agent 自己选。

### 4.3 整合、更新与遗忘（记忆的生命周期）

| 机制 | 代表工作 | 要点 |
|---|---|---|
| 反思与打分 | **Generative Agents**（arXiv 2304.03442） 📄 `2304.03442v2.pdf` | 按重要性、新近度、相关度三项打分来检索；定期反思，把底层事件提炼成高层结论。后来大量工作都沿用这套打分 |
| 显式增删改 | **Mem0**（arXiv 2504.19413） 📄 `2504.19413v1.pdf` | 新信息进来时由 LLM 选 ADD / UPDATE / DELETE / NOOP；有图记忆变体 Mem0g |
| 离线整合 | **Sleep-time Compute**（arXiv 2504.13171） 📄 `2504.13171v1.pdf` | 空闲时预先整理和推理记忆，把推理时的计算挪到离线 |
| 基于复现的整合 | **RecMem**（arXiv 2605.16045） 📄 `2605.16045v1.pdf` | 根据反复出现的模式来触发整合，兼顾效率和效果 |
| 检索即再巩固 | **Retrieval-Driven Memory Reconsolidation**（arXiv 2609.16053） 📄 `2609.16053v1.pdf` | 借用神经科学的"再巩固"概念：记忆被取出时顺便修订（具体方法本次未细读） |
| 选择性遗忘 | **Selective Forgetting**（arXiv 2608.28978） 📄 `2608.28978v1.pdf` | 在图存储上加遗忘模块，删掉过时记忆，同时保持关系结构 |
| 时间衰减与治理 | **SSGM**（arXiv 2603.11768） 📄 `2603.11768v2.pdf` | 按距上次被检索的时间做 Weibull 衰减；同时讨论记忆演化带来的稳定性和安全风险 |
| 增量而非重写 | **ACE**（见 3.3） | 整体重写会导致记忆坍缩，应该只追加增量条目 |

**一个共识**：写入时只做轻量结构化，重整合放到离线或语义边界处做；遗忘要有原则（时间衰减、被取代、有效性区间），不能只追加不删除。

## 五、动态加载：在对的时机把对的记忆放进上下文

核心问题：上下文有限，什么常驻、什么按需取、什么时候取、由谁决定取。

### 5.1 设计原则：just-in-time context
- **Anthropic《Effective context engineering for AI agents》**（2025-09，据我所知）
  https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
  - 上下文里只放轻量的"指针"（文件路径、查询语句、链接），运行时再由 agent 用工具按需加载全文。
  - 采用混合策略：少量关键信息（如 CLAUDE.md）预先加载，其余按需探索。
  - 上下文被看作有边际递减效应的有限资源（context rot），目标是用最少的高信号 token 完成任务。

### 5.2 渐进式披露（progressive disclosure）
- 用在 Skills 机制上，分三级加载：会话开始时只放每个 skill 的名称和描述；模型判断要用某个 skill 时才注入 SKILL.md 正文；正文里引用的子文件再按需读取。
- **Is Progressive Disclosure All You Need for Long-Context Agents?**（arXiv 2607.17598） 📄 `2607.17598v1.pdf`：第一个把这种模式和混合检索器做对照的实验（InfiniteBench）。结论是渐进式披露省的是上下文空间，并不让模型更聪明：语料大时有明显收益，单本书这种规模时收益不大。

### 5.3 何时检索、检索什么（学出来的检索策略）

| 工作 | 要点 |
|---|---|
| **MemCon / Memory as a Controlled Process**（arXiv 2607.13591） 📄 `2607.13591v3.pdf` | 把记忆操作建模成 MDP，动作包括检索、复用计划、再检索、整合、跳过；用轻量 UCB bandit 在线学习，不额外调用 LLM，几十个任务内就收敛。发现"再检索"基本只在卡住时有用 |
| **RIME / Remember by Asking**（arXiv 2609.34438） 📄 `2609.34438v1.pdf` | 分级回退：先查压缩记忆，查不到再取原始对话及相邻轮次；检索过程本身也推动记忆演化 |
| **ERSkill**（arXiv 2608.12720） 📄 `2608.12720v2.pdf` | 不再用固定的稠密检索，而是让检索技能随查询演化，做到按需定制 |
| **R²-Mem**（arXiv 2605.13486） 📄 `2605.13486v1.pdf` | 用反思得到的经验来指导记忆搜索 |
| **MRAgent**（见 4.2） | 推理驱动的图遍历：根据已有证据推断新的检索线索 |
| **Memory-R1 的 Answer Agent**（见第二章） | 用 RL 学会从检索结果中过滤掉无关记忆，再作答 |

### 5.4 让模型自己管理上下文
- **MemGPT**：最早由模型通过函数调用在上下文和外部存储之间换页。
- **Context as a Tool / CAT**（arXiv 2512.22087） 📄 `2512.22087v1.pdf`：把上下文维护做成一个可调用的工具，agent 像选择其他动作一样决定何时调用；调用时总结工作记忆、更新长期记忆段。场景是长周期 SWE agent。
- **Sculptor**（arXiv 2508.04664） 📄 `2508.04664v2.pdf`：给 LLM 一套主动管理上下文的工具（分段、隐藏、恢复、检索等）。
- **LLM Agents Are Latent Context Managers**（arXiv 2606.30005） 📄 `2606.30005v5.pdf`：指出前沿模型对自己的上下文状态"缺乏本体感"，通过把状态信息暴露给模型（state proprioception）来激发它自我管理上下文的能力。
- 与第二章的 **CompactionRL**、**MemAgent** 呼应：从"给模型工具"走向"用 RL 训练模型使用这些工具"。

### 5.5 实践组合（综合以上的个人归纳）

| 层 | 放什么 | 怎么加载 |
|---|---|---|
| 常驻层 | 系统提示、核心记忆（用户画像、项目约定）、记忆和技能的**索引** | 每轮固定注入，尽量短，便于命中 prompt cache |
| 按需层 | 情景细节、文档全文、skill 正文、历史轨迹 | agent 用工具检索，或按渐进式披露逐级展开 |
| 后台层 | 整合、去重、遗忘、反思提炼 | 离线或空闲时运行（sleep-time），也可以在语义边界触发 |

## 六、评测：分数要谨慎看

- 主流 benchmark：LoCoMo、LongMemEval；较新的有 BEAM、MemOps（https://arxiv.org/abs/2607.12893）。
- 各家 90%+ 的分数大多是自己报的，实验设置不同，无法直接比较。汇总见：https://mem0.ai/blog/state-of-ai-agent-memory-2026
- 有审计发现 LoCoMo 的 LLM 评判器最多会接受 63% 故意答错的答案，约 6.4% 的标准答案本身有错。
- 有人独立测了 Mem0 开源版，结果远低于官方数字：https://dev.to/everest_an/-i-benchmarked-ai-agent-memory-in-2026-and-the-numbers-tell-a-different-story-than-the-marketing-2ae4
- 记忆安全（记忆投毒、回滚、遗忘）正在升温，见下方安全综述。
